# NNNN — Short imperative title

- **Status:** Proposed | Accepted | Superseded by [NNNN](./NNNN-...md) | Deprecated
- **Date:** YYYY-MM-DD
- **Deciders:** (names or roles)

## Context

What's the situation that forced a decision? Include facts, not opinions: file sizes, dependency versions, deadlines, prior incidents. Keep to one or two paragraphs.

## Decision drivers

- Bullet list of the constraints that actually moved the decision (timeline, expertise, platform support, etc.).
- Each driver should be testable — "we have ~8 weeks before launch" is a driver; "we want clean code" is not.

## Considered options

Brief one-paragraph description of each option that received serious consideration. Two or three is usually right. If only one option exists, you probably don't need an ADR — just write the code.

## Decision

What we're doing. State it as a single sentence in the imperative, then expand with 1–3 paragraphs of detail.

## Consequences

- **Positive** — what gets better.
- **Negative** — what we're paying or postponing.
- **Neutral** — things that change but aren't clearly better or worse.

## Follow-ups

- Concrete next steps, with owners or links to issues/ADRs.
- "We will write ADR NNNN+1 when X happens" is a valid follow-up.
